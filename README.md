# SAVR_WIKI — Savage Rebelz (SAVR) alliance field manual

The alliance knowledge base for **Savage Rebelz (SAVR)** on **Server #297** of the mobile strategy game **Last Asylum: Plague**. One static Next.js site holding every event file, field guide, strategy brief, FAQ answer and planning window the alliance needs — with a local instant search index, a visual event calendar, a screenshot library, an installable PWA shell and a Decap CMS workflow so leadership can publish without touching code.

**What it solves:** members stop guessing event windows. Each event page turns a schedule into an objective, a phase plan, a reward table, a checklist and the mistakes that cost points; the calendar shows where Survival Battle and Alliance Duel overlap so one action can feed two scoreboards; and the AvA command centre wires all of it into a six-day playbook.

Alliance identity (name, callsign, server, Discord, contact, stats) lives in [`data/site.json`](data/site.json) and flows into the header, footer, metadata, manifest and OpenGraph tags — change it there once to rebrand the text. The **Last Asylum wordmark artwork** ships in `public/brand` and is regenerated from `assets/brand` with `npm run assets:brand` (see [Name, wordmark and crest](#name-wordmark-and-crest)).

> **Fan-made resource.** Not affiliated with or endorsed by 37GAMES or Wiseness. Event schedules, point values and rewards change by server, season and game version. Always verify the live in-game event screen. The Last Asylum wordmark and backdrop are the game's own artwork, used here to identify the game; the gallery boards are clearly labelled placeholder material. Replace the placeholders with your own screenshots or assets you have permission to use.

## Quick start

```bash
npm install
npm run dev
```

Open http://localhost:3000. The dev script builds the search index first, then starts Next.js.

```bash
npm run build       # static export to ./out
npm run preview     # serve ./out at http://localhost:4173
npm run typecheck
npm run lint
```

Node 20+ is required. The site uses `output: "export"`, so `npm run build` produces static files that deploy to Vercel, Cloudflare Pages, Netlify or any static host.

## Stack

- Next.js 15 App Router + React 19 + TypeScript
- Tailwind CSS 3.4 with a custom dark tactical design system
- shadcn-style local UI primitives (Button, Card, Badge, Accordion, Tabs)
- Lucide icons
- MDX content compiled at build time with `next-mdx-remote` and `remark-gfm`
- JSON data collections for calendar, gallery, FAQ and site settings
- Static local search index generated by `scripts/build-search-index.mjs`
- Decap CMS for no-code editing
- Static export for Vercel and Cloudflare Pages compatibility

## Content editing

Day-to-day updates are designed for **Alliance Leadership**, not developers.

### Decap CMS

1. Local editing:
   ```bash
   npm run dev
   npm run decap   # in a second terminal
   ```
   Open `/admin/cms/` and choose the "local backend" login.

2. Production editing requires a GitHub repository and an OAuth proxy. See [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). Once configured, editors log in through GitHub and publish through the CMS.

Collections:

- **Event files** — all frontmatter sections, images and walkthrough steps
- **Field guides** — overview, priorities, actions, resources, visual steps, tips, mistakes
- **Strategy briefs** — objective, actions, requirements, optimisation, metrics
- **FAQ** — category, question, answer, tags
- **Event calendar** — dates, category, description, source, overlap IDs, detail link
- **Image library** — upload, caption, category, tags, credit
- **Alliance identity** — alliance name, callsign, server, Discord, contact, stats, disclaimer

### Event clock and timezones

Every window in `data/calendar-events.json` is stored on the **in-game clock**, which runs at **UTC-2** — two hours behind UTC and three hours behind UK summer time. A stored `...Z` value is server wall-clock time, not a UTC instant: `2026-10-19T00:00:00Z` means midnight on the server, which is 02:00 UTC. The site renders those values in whichever clock the visitor picked:

- **Server** — the in-game clock (`UTC-2`), used by default.
- **My local** — a fixed offset the player sets with the header clock chip (or the calendar panel), the way the game asks for a timezone. The choice is stored in `localStorage` and every calendar label, countdown, event list and day grid follows it.

Nothing is stored in the visitor's timezone, so editors always type the in-game time in the CMS. Countdowns read the device clock every second, so the current day rolls over at midnight without a rebuild. `lib/time.ts` holds the offset maths (`SERVER_OFFSET`, `displayOffset`, `nowOnServerClock`) and `components/time/` the provider, clock chip, panel and time labels.

### Name, wordmark and crest

The alliance name and callsign in `data/site.json` drive the text identity (titles, metadata, footer, JSON-LD). Two pieces of artwork sit behind the branding:

```bash
npm run assets:brand   # alliance wordmark, crest and app icons
npm run assets:logo    # the game's Last Asylum wordmark (homepage hero)
```

The alliance generator reads `assets/brand/savr-wordmark-source.jpg` and writes:

| Output | Used by |
| --- | --- |
| `public/brand/savr-wordmark-420.avif` / `-840.avif` / `.webp` | header, footer, mobile drawer, admin, OG art |
| `public/brand/savr-mark.png` | square crest in the hero dossier bar |
| `app/icon.png`, `app/apple-icon.png`, `public/icon-192.png`, `public/icon-512.png`, `public/favicon-32.png` | browser tab, PWA install, home screen |

The logo generator reads `assets/brand/last-asylum-wordmark-source.png` (transparent PNG) and writes `public/brand/la-wordmark-245.avif` / `-490.avif` / `.webp`, which appear only where the page refers to the game itself — the homepage hero lockup (`<BrandWordmark art="game" />`).

To rebrand the alliance: drop the new artwork over `assets/brand/savr-wordmark-source.jpg` (black background, landscape lettering) and rerun `npm run assets:brand`. Keep the name/callsign in `data/site.json` in sync so the artwork and the text identity agree. To swap the game artwork, replace `assets/brand/last-asylum-wordmark-source.png` and run `npm run assets:logo`.

The MDX body of event/guide/strategy files remains editable in the CMS markdown pane, but advanced visual components (`<Callout>`, `<Screenshot>`) are best left to the templated fields. See [docs/CONTENT.md](docs/CONTENT.md).

### Editing files directly

Content is plain MDX + JSON in Git. Replace the placeholder text and images, update `updated` dates, and rebuild. The dynamic routes are generated from filenames.

### Gift codes

`/tools/gift-codes/` reads [`data/gift-codes.json`](data/gift-codes.json). A GitHub Actions schedule runs [`scripts/refresh-gift-codes.mjs`](scripts/refresh-gift-codes.mjs) at minute 0 of every hour (UTC), follows the newest in-game-checked list, removes expired and duplicate codes, and commits only when the working set changes. That commit triggers the normal static deployment. The workflow starts once it is pushed to the default branch; see [docs/CONTENT.md](docs/CONTENT.md#gift-codes).

### Alliance roster

`/roster/` reads [`data/roster.json`](data/roster.json). [`scripts/refresh-roster.mjs`](scripts/refresh-roster.mjs) reads the public alliance leaderboard at server reset (00:00 on the in-game clock, UTC-2) and the GitHub Actions schedule commits the result, which triggers the normal static deployment. The script refuses to publish a truncated or malformed roster, so a failed read leaves the previous list live; see [docs/CONTENT.md](docs/CONTENT.md#alliance-roster).

### Hero roster

`/guides/know-your-heroes/` renders one cheat sheet per hero: rank, class/role, summary, key skills and planning facts, filterable by class, role and free text. The data is generated from the published roster rather than hand-written:

```bash
npm run heroes:import   # rewrites data/heroes.json from last-asylum.com/heroes.html
npm run build           # rebuilds the search index and every page
```

Portraits live in `public/images/heroes/{slug}.webp`. Drop a file in with the hero's slug and rerun the importer to wire it up; heroes without a portrait render a themed placeholder card. Cut the artwork out on a transparent background and keep it around 500×600 — the card draws it with `object-contain` above a dark HUD panel, so any leftover backdrop shows as a bright slab. Each hero is also indexed into search, linking straight to `/guides/know-your-heroes/#hero-{slug}`.

## Search

`npm run build:search` reads every content file and generates `public/search-index.json` (gitignored — it is rebuilt at the start of both `npm run dev` and `npm run build`). The client loads it lazily and performs weighted local matching on titles, tags, descriptions and full text. Search works without a server or a page reload, and supports:

- Instant results in a command dialog (`Ctrl/⌘ + K` or `/`)
- Full search page with type and category filters
- Results across events, guides, heroes, strategies, FAQ, calendar and images

## Images

The site ships with 22 generated tactical reference boards in `/public/images/gallery`. They are intentionally labelled **placeholder**. Replace them with real screenshots through the CMS or by dropping files into `public/images/uploads` and updating the image fields.

The alliance wordmark is real artwork, not placeholder: it lives in `public/brand` and is regenerated from `assets/brand` with `npm run assets:brand` (see [Name, wordmark and crest](#name-wordmark-and-crest)).

Because the project uses static export, Next.js image optimisation is disabled (`images.unoptimized`). The `<Image>` component still provides responsive sizing attributes and lazy loading, and the local assets are pre-sized. If you deploy only to Vercel and want runtime optimisation, remove `output: "export"` and `unoptimized` — see the deployment notes.

## Themes

Three palettes ship with the site. **Vivid is the default**; the original neon palette is still available, alongside a blue/purple direction.

| Theme | Mood | `--primary` | `--accent` |
| --- | --- | --- | --- |
| **Vivid** (default) | tangerine and magenta on warm ink | `#fa8c2d` | `#f0449c` |
| **Aurora** | azure and violet over deep indigo | `#4898fe` | `#8b5cf6` |
| **Neon** | spring green and emerald, the original Savage Rebelz palette | `#34e07f` | `#10b981` |

Pick one from the palette chip in the top bar, or from the Appearance tiles in the mobile drawer. The choice is saved in `localStorage` under `savr.theme` and written to `<html data-theme="…">`; a tiny inline script in the root layout applies it before first paint, so a returning visitor never sees a flash of the wrong palette. The browser's `theme-color` bar is kept in step too.

Where it lives:

- [`styles/globals.css`](styles/globals.css) — the token contract, once per `[data-theme="…"]` block: surfaces, `--primary`/`--accent`, `--primary-rgb` for alpha glows, `--ink`/`--panel`/`--well` for chrome, `--grid-rgb`, `--art-filter` and the headline gradient stops.
- [`lib/themes.ts`](lib/themes.ts) — the registry (label, swatches, chrome colour), `DEFAULT_THEME` and the storage key.
- [`components/theme/`](components/theme/) — the provider (persistence, cross-tab sync, meta tag) and the header/drawer switchers.
- [`tailwind.config.ts`](tailwind.config.ts) — maps the tokens to utilities such as `bg-primary`, `text-primary-soft`, `bg-ink`, `bg-panel`, `bg-well`, `text-warning` and `text-success`.

Adding a fourth palette means adding one `[data-theme="…"]` block with the same variables and one entry to `THEMES`; no component needs to change.

What deliberately does **not** move with the theme:

- the SAVR wordmark and crest artwork, and their green glow;
- hero class colours (red / blue / green) and the UR gold — defined as fixed `hero.*` values in `tailwind.config.ts`;
- semantic status colours: `warning` amber, `success` green, `destructive` coral.

Illustrations, cover art and gallery reference boards follow the palette through `--art-filter` / the `.themed-art` class (the backdrop, event covers, gallery grid, lightbox and in-page visual references). If you add an authentic in-game capture that must stay true-to-source, remove that class from its `<Image>`.

Body copy on each theme's background sits between 16.4:1 and 16.8:1, muted metadata 8.2–8.5:1 and primary accent text 6.6–13:1, so all three clear WCAG AA.
